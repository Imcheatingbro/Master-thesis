You are an independent, strict semantic judge for event-structure extraction.

Task:
Given one original event/state span and a complete flat list of extracted semantic units for that span, judge every provided unit.

Evaluation boundary:
- This is precision-oriented evaluation. Judge only provided units; do not penalize omissions.
- Do not reward a unit merely because its text occurs in the span.
- Do not assume that the extractor's role choice or hierarchy is correct.
- Consider whether an alternative role, flatter representation, sibling relation, or different available parent would be semantically better.
- Do not evaluate JSON/schema validity, substring validity, depth limits, or counts; code handles these checks.
- Do not compare methods and do not reconstruct the outer causal relation.

Scores:
- 1 = clearly correct
- 0.5 = defensible but materially imperfect or ambiguous
- 0 = incorrect
- null = not applicable

Fields:
- s — semantic usefulness: Does this unit contribute a distinct, meaningful proposition/entity/modifier worth representing in the KG? Textual presence alone is insufficient. A vacuous fragment, duplicate restatement, or wrapper that adds no distinct information must score below 1.
- r — role correctness: Is this the best semantic role for the value in this span? A merely possible role is 0.5 when a clearly better role exists.
- m — minimal and complete scope:
  - 1: concise but complete for its role; no separable participant/modifier is unnecessarily swallowed.
  - 0.5: slightly broad/narrow, or an unnecessary wrapper that remains coherent and partly useful.
  - 0: a fragment cannot fill the role, or the value absorbs multiple independently representable components and therefore has the wrong granularity.
- a — attachment correctness:
  - 1: the parent-child/modifier relation is semantically licensed and the parent is the nearest appropriate one among the units supplied.
  - 0.5: attachment is plausible but ambiguous or not the best available analysis.
  - 0: the relation is unsupported or another supplied parent is clearly better. Surface adjacency or textual containment alone never proves attachment.
- e — one short error label, or null only when all applicable fields equal 1.

Unit rules:
- node: score s, r, m; a = null.
- attribute: score s, r, a; use m only when its value is clearly too broad/narrow, otherwise m = null.
- child_link: score a only; s = r = m = null.

Calibration examples (constructed independently of the extractor and evaluation set):

Correct example:
Span: "the council approved the budget on Tuesday"
Units: Action="approved"; Actor="council"; Theme="budget"; Time="Tuesday" attached to Action="approved".
Judgment: the three nodes and Time attribute have all applicable scores 1 because they are distinct, concise, and correctly attached.

Incorrect counterpart:
Span: "the engine suddenly failed"
Units: Action="failed"; Theme="engine"; Content="the engine suddenly failed".
Judgment: Action and Theme may score 1. The Content wrapper must have s below 1 and m below 1 because it restates the already represented event while swallowing separable components.

Correct attachment example:
Span: "workers repaired the bridge in Boston"
Units include Action="repaired", Actor="workers", Theme="bridge", Location="Boston", with Location attached to Action.
Judgment: the Location attachment is correct.

Incorrect attachment counterpart:
For the same span and units, Location="Boston" attached to Actor="workers" must have a below 1. Proximity to "workers" would not license that parent when the repair event is the appropriate parent.

Allowed error labels:
unsupported_value, not_meaningful_unit, redundant_unit, wrong_role, too_broad, too_narrow, wrong_parent, unsupported_hierarchy, unclear, other

Return strict JSON only. No markdown and no explanation outside the JSON.
Return every input unit exactly once, preserving its id.

Input:
{input_json}

Output schema:
{
  "span_id": "same span_id as input",
  "units": [
    {
      "id": "unit id",
      "s": 1,
      "r": 1,
      "m": 1,
      "a": null,
      "e": null
    }
  ]
}
