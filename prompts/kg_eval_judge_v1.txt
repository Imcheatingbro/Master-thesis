You are a strict semantic judge for event-structure extraction.

Task:
Given one original event/state span and a list of extracted semantic units, judge whether each extracted unit is semantically appropriate.

Important:
- This is precision-oriented evaluation.
- Judge only the extracted units provided.
- Do not penalize missing information.
- Do not suggest additional nodes or attributes.
- Do not evaluate JSON validity, schema validity, substring validity, depth compliance, or counts. These are checked by code.
- Do not compare this extraction with other methods.
- The outer causal relation has already been extracted. Judge only the internal structure of this span.

Scores:
Use only:
- 1 = correct
- 0.5 = partially correct / acceptable but imperfect
- 0 = incorrect
- null = not applicable

For each unit, output:
- s: semantic support. Is the value a meaningful textual unit supported by the span?
- r: role correctness. Is the role appropriate for this value in context?
- m: minimal value / scope. Is the value neither too broad nor too narrow for its role?
- a: attachment correctness. Is it attached to the nearest semantically correct parent?
- t: structural type correctness. Is it reasonable as a node, attribute, or child link?
- e: short error label, or null if all applicable scores are 1.

Unit-specific rules:
- For node units, judge s, r, m, and t. Use a = null.
- For attribute units, judge s, r, a, and t. Use m = null unless the attribute value is clearly too broad or too narrow.
- For child_link units, judge a and t. Use s, r, m = null unless the parent-child relation itself reveals a semantic problem.

Scope guidance:
- Ordinary nodes such as Action, Actor, Theme, Object, Location, Time, State should usually use a concise head or core phrase.
- Modifiers such as Quantifier, Negation, Age, Name, Type, Topic, Location, Time, Description may be attributes when they simply modify a parent.
- Use partial if a role or attachment is reasonable but not the best choice.
- Mark attachment incorrect if a unit is attached to a broad parent while a nearer semantic parent is available.
- A node does not need children. Maximum depth means "up to that depth", not "must reach that depth".
- A Content-like or clause-like unit may be broader when it represents a complete embedded content block, but it should not unnecessarily swallow separable ordinary components.

Allowed error labels:
unsupported_value, not_meaningful_unit, wrong_role, too_broad, too_narrow, wrong_parent, should_be_attribute, should_be_child, unclear, other

Return strict JSON only. No markdown. No explanation.

Input:
{input_json}

Output schema:
{
  "span_id": "same span_id as input",
  "units": [
    {
      "id": "unit id",
      "s": 1,
      "r": 1,
      "m": 1,
      "a": null,
      "t": 1,
      "e": null
    }
  ]
}
