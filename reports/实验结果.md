# 实验结果

## 第一部分：RAG 数据库与 RAG 参数消融实验

### 1.1 两套 RAG 数据库

本项目保留两套可由检索器切换的正例支持库。通用数据库用于跨领域或早期 Pattern/KNN 检索，CNC 专用数据库用于本章最终的 CNC RAG 消融与完整测试。两套数据库均只向模型提供因果关系结构和抽取格式示范，不承担负例分类训练。

| 数据库 | 数据来源与规模 | 数据结构 | 检索用途 | 数据隔离 |
|---|---|---|---|---|
| 通用 Pattern/BGE 数据库 | 由 SCITE、SemEval 与 ADE 因果样本合并；2,365 条正例，包含 2,364 个唯一句子和 1,389 个大小写归一化后的 unique patterns | 每条记录包含一个 cause–effect pair、原句及 causality phrase | 可执行 Pattern、KNN 与 KNN+Pattern 检索；KNN 使用 BAAI/bge-small-en-v1.5 的 384 维本地 embedding cache | ADE 数据清洗时剔除了与该库规范化句子重叠的样本；最终 CNC 实验不使用此库 |
| CNC 专用数据库 | 600 条 CNC train-only 正例，覆盖 587 个文档、899 条关系和 229 个大小写归一化后的 unique patterns | 支持一个句子包含一至多条 cause–effect triples，并保存一个或多个 signals | 用于本章 CNC 的 Pattern、KNN、KNN+Pattern 与 random 对照 | 与固定 validation/test 的 sample ID、原文和 doc_id 重叠均为 0 |

通用数据库的原始 Pattern 文件为 RAG Database/comb_SCITEsemADE_CausalityPattern.csv。CSV 中保留的旧 embedings 字段不作为当前运行时输入；项目使用 RAG Database/bge-small-en-v1.5_examples.jsonl 与对应的 NumPy cache 重建 KNN 检索。CNC 专用数据库则使用 RAG Database/cnc_examples.jsonl 与 cnc_embeddings.npy，并通过 rag_database 参数显式选择，避免两套支持库在实验中混用。

### 1.2 CNC 专用数据库的构建与 Pattern 处理

CNC 专用数据库最初包含来自 train、validation 和 test 的支持样本。为保证 validation 可用于 RAG 参数选择、test 保持最终 held-out 评测，数据库最终全部替换为 train 正例。替换尽量保持单/多关系、是否具有原始 gold signal 和文本长度分层；受候选数量限制，9 条样本仅在文本长度层级上采用相邻层级替换。最终数据库与 validation/test 的 ID、规范化文本和文档均无重叠。

| Pattern 来源 | 样本数 | 定义 |
|---|---:|---|
| CNC 原始 gold signal | 469 | 原数据中的显式 causal signal |
| DeepSeek explicit connective | 107 | 按 Pattern RAG 方法从原句抽取的显式 connective |
| DeepSeek implicit lexical proxy | 24 | 隐式因果句中为现有 matcher 选择的原句事件词或短语 |
| 合计 | 600 | 每条 support 至少具有一个可用于 Pattern 检索的 signal |

所有补齐的 Pattern 均通过原句连续子串校验。24 条隐式因果句没有独立的显式 causal connective，因此使用 blocked、became violent、attack 或 protesting 等事件词/短语作为 lexical proxy，并要求至少包含一个英文单词、不能是纯标点。这使全部支持样本都能进入现有 Pattern matcher，但其方法边界必须明确：这 24 条执行的是 event-word matching，不是严格的 causal-connective matching，不能与其余 576 条显式 connective 样本视为完全同质。

数据库不额外加入负例。原因是本研究使用 RAG 提供正例结构和抽取格式，而固定 10-shot Prompt 已包含 5 条正例和 5 条负例；参考方法的检索数据库同样只包含因果正例。该设计不证明负例检索无效，只表示在 RAG 并非研究主线、已有固定负例示范且计算预算有限的条件下，不再扩展数据库类别组成消融。

### 1.3 消融设计：按模型家族选择代表模型

本研究引入 RAG 的直接目的，是检验相关因果示例能否进一步提高本地模型的 detection 和 extraction 性能。理想设计可为四个本地模型、三个数据集和多个 k 值分别搜索最优配置；仅按 k=1、3、5 计算就会产生至少 36 个模型–数据集–k 组合，若再加入 RAG-off、random、RAG-only 和不同检索策略，运行量还会继续扩大。这与 RAG 在本研究中的辅助实验定位和本地推理预算不相称。

选择 CNC 进行 RAG 参数消融，是因为它是本项目所用数据集中结构最复杂、抽取难度最高的一组。其 Gold argument 通常是较长的完整事件或状态 span，而不是较短的实体 anchor；同一句中可能包含多条、链式或嵌套的因果关系，并包含大量没有显式 connective 的隐式因果案例。在此前相同项目的跨数据集实验中，微调前的 CNC 抽取分数也是所有数据集中最低的。因此，CNC 能够同时检验 RAG 对长 span 边界、多关系枚举和隐式语义判断的帮助，是比简单单关系数据更有区分度的消融测试场景。

因此，本研究采用“每个模型家族选择一个代表模型进行 k 消融”的资源受限设计，而不在同一家族的全部模型上重复相同搜索。Phase 1 首先在相同的 CNC validation split 上比较四个本地模型的 zero-shot、RAG-off 表现。CNC validation 包含 500 条样本，其中 264 条为因果正例、236 条为非因果样本，共有 366 条 gold relations。

| 模型 | Detection F1 | Strict all F1 | Anchor all F1 |
|---|---:|---:|---:|
| Qwen3.6 35B A3B | 0.828 | 0.443 | 0.341 |
| Qwen3.6 27B No Thinking | **0.860** | 0.471 | 0.452 |
| Gemma 4 26B A4B QAT | 0.821 | 0.400 | 0.392 |
| Gemma 4 31B QAT | 0.841 | **0.531** | **0.549** |

在 Qwen 系列中，Qwen3.6 27B No Thinking 的 Detection、Strict all 和 Anchor all F1 均高于 Qwen3.6 35B A3B，因此被选为 Qwen 家族的 RAG 消融模型。在 Gemma 系列中，Gemma 4 31B QAT 的 Strict all 和 Anchor all F1 均明显高于 Gemma 4 26B A4B QAT，因此被选为 Gemma 家族的 RAG 消融模型。该设计以各家族 zero-shot 表现最好的模型作为参数选择代表：Qwen 依据主指标 strict_token_f1 选择 k，Gemma 依据主指标 anchor_window 选择 k。它并不假设同一 k 对家族内每个模型都是各自最优，而是在资源有限时避免对四个模型重复执行完整消融。

参数选择只使用 validation，不根据完整 test 结果反向调整 k、Prompt 或数据库。固定推理设置为 temperature 0、context length 8,192。Fixed Prompt 含 10 条固定示例，其中 5 条正例、5 条负例；KNN+Pattern RAG 在每个 k 下分别返回 k 条 Pattern 和 k 条 KNN 示例，因此动态示例总数为 2k。Random 对照从同一份 600 条 train-only 正例库中返回相同数量的示例。表中同时报告 all-samples 和 detected-only 指标：前者用于参数选择，后者用于诊断在 Gold 与 Pred 均为正例时的关系抽取质量。

### 1.6 两个模型家族的 RAG 消融结论与参数决策

1. **RAG 在 zero-shot 条件下对两个代表模型都有帮助。** Gemma 31B 的最佳 Anchor all F1 从 0.549 提高至 0.600，最大增益为 0.051；Qwen 27B 的 Strict all F1 从 0.471 提高至 0.508，最大增益为 0.037。由于没有设置 zero-shot+random，对这部分提升仍应保留“相关检索与新增 demonstrations 共同作用”的解释边界。
2. **Fixed Prompt 上的结果具有明显的模型家族差异。** Gemma 31B 的 Fixed/RAG-off Anchor all/detected-only F1 为 0.638/0.729，加入 RAG 后均未超过该基线；Qwen 27B 的 Fixed+RAG k=3 则将 Strict all/detected-only F1 从 0.475/0.558 提高至 0.530/0.611。RAG 是否能在优化后的固定示例上继续产生净收益，不能从一个模型直接推广到另一个模型。
3. **相关检索优于随机示例，但 Qwen 上的证据更强。** Gemma 在 k=3 时，Fixed+RAG 相对 Fixed+Random 的 Anchor F1 提高 0.011；Qwen 在 k=3 时，Strict all F1 提高 0.049。这说明 KNN+Pattern 检索确实包含与目标输入相关的有效信息，而不仅是通过增加上下文示例改变模型行为。
4. **最优 k 取决于模型家族及其主指标。** Gemma 中增大 k 主要提高 recall、降低 precision，Fixed+RAG 的 Anchor F1 随 k 增大而下降，因此在必须保留 RAG 的条件下选择成本最低且分数最高的 k=1。Qwen 的 Strict all F1 从 k=1 的 0.501 提高至 k=3 的 0.530，随后在 k=5 降至 0.520，因此选择 k=3。最终参数为：Gemma 家族使用 KNN+Pattern RAG、k=1；Qwen 家族使用 KNN+Pattern RAG、k=3。
5. **最终 test 只比较非检索对照与 validation 选出的 RAG 配置。** 对两个代表模型均保留 Fixed 10-shot + RAG-off 作为固定对照组，并各自测试一个仅根据 validation 主指标选出的最佳 RAG 配置：Gemma 31B 使用 Fixed 10-shot + RAG1，Qwen 27B 使用 Fixed 10-shot + RAG3。Gemma 的 RAG1 是三个 RAG 候选中的最佳配置，并非包括 RAG-off 在内的总体最优配置；Qwen 的 RAG3 则同时是其最佳 RAG 配置并在 validation 上超过 RAG-off。两者仍遵循相同的选择规则：RAG-off 用于提供无检索基线，k 只在 RAG 候选内部通过 validation 确定，完整 test 仅评估预先选定 RAG 相对基线的泛化收益，不再用于选择 k。

#### RAG 消融综合结论

总体而言，RAG 在 CNC 上能够提供有效信息，但其增量价值取决于模型家族、基础 Prompt 和评价指标。Gemma 31B 已能从优化后的 Fixed 10-shot 中获得较充分的任务信息，继续加入全正例动态示例造成 precision 下降，因此 k=1 只是三个 RAG 候选中成本最低、表现最稳妥的配置，并不超过 RAG-off。Qwen 27B 则能从相关动态示例中获得明确的端到端抽取增益，其中 k=3 在 Strict all、Strict detected-only 及检索相对随机增益之间形成最佳平衡。

由于 RAG 不是本研究的唯一主线，实验没有对四个模型和三个数据集进行穷举搜索，而是依据 Phase 1 zero-shot 结果，在每个模型家族中选择表现最好的一个模型：Qwen3.6 27B No Thinking 和 Gemma 4 31B QAT。该设计既保留了家族差异，又把计算开销限制在合理范围内。结果最终支持使用家族特定参数，而不是全模型共享同一个 k：Qwen 使用 k=3，Gemma 使用 k=1。相应地，最终 test 对每个代表模型只保留 Fixed 10-shot + RAG-off 和 Fixed 10-shot + validation-selected RAG 两组配置，从而将 test 的作用限定为检验 RAG 增益能否泛化，而不是继续搜索参数。

### 2.4 总体结果分析与最终结论

1. **若以端到端因果关系抽取为核心，Gemma 4 31B QAT + Fixed 10-shot + RAG1 是最终最佳本地配置。** 它同时取得最高的 Strict all F1（0.562）和 Anchor all F1（0.644），Detection F1 为 0.844，Strict/Anchor detected-only F1 为 0.644/0.739。它不是每个单项指标都最高，但在 detection、完整测试集抽取和已检出样本抽取之间形成最好的综合平衡。
2. **此前统一运行的 RAG1 在四个基础模型上的平均影响小幅、总体正向，但存在模型依赖。** 四模型宏平均 Detection Accuracy、Detection F1、Strict all F1 和 Anchor all F1 分别提高 0.023、0.008、0.002 和 0.006；Anchor all F1 在四个模型中的三个模型上提高。Gemma 31B 的各项核心指标均提高，是最明确的受益模型；Gemma 26B 的 Anchor all F1 从 0.568 降至 0.553。随后完成的 Qwen validation 消融进一步确认，全模型共享 k=1 不是最合适的最终设计，Qwen 家族应改用 k=3。
3. **按各模型的主指标观察，Detected-only 揭示了 RAG 收益的不同来源。** Qwen 35B 的 Strict all F1 从 0.447 小幅提高至 0.450，但 Strict detected-only F1 从 0.542 降至 0.534，说明其端到端增益主要来自 detection 校准。Qwen 27B 的 Strict all/detected-only F1 分别从 0.491/0.589 降至 0.476/0.577；虽然其辅助 Anchor 指标提高，但不能据此写成 Qwen 主抽取指标得到改善。Gemma 26B 的主指标 Anchor all/detected-only F1 从 0.568/0.680 降至 0.553/0.656，而 Gemma 31B 的 Anchor all/detected-only F1 从 0.629/0.732 提高至 0.644/0.739。
4. **CNC 微调提高了部分模型的 detection，但总体没有超过最佳 31B 基础模型的端到端抽取性能。** Qwen3-14B QLoRA 的 Detection F1 为 0.849，是整张表最高值，但其主指标 Strict all F1 只有 0.541；Qwen 微调模型中表现最好的 Qwen3-8B Normal 取得 0.551，Gemma 微调模型中表现最好的 Gemma 4 E4B 取得 Anchor all F1 0.600，均低于 Gemma 31B + RAG1 对应的 0.562/0.644。Hard-v2 虽将 Qwen3-8B 的 Detection F1 从 0.798 提高至 0.842，却使 Strict all F1 从 0.551 降至 0.533，说明困难样本重复采样改善的是正例覆盖，而不是关系数量、方向和 span 边界。Gemma 4 12B v1 则发生输出类别坍缩，只预测 39 个正例，Detection recall/F1 为 0.066/0.123，Strict/Anchor all F1 仅为 0.085/0.082；其 detected-only 高分只来自 36 条成功检出的正例，不能代表总体性能。结合 CNC 的长事件 span、多关系结构和大量隐式因果案例，以及微调前它在跨数据集实验中已经是得分最低的数据集，这些结果表明，当前 1,537 条唯一训练样本能够改善部分 detection 行为，却不足以让较小模型稳定学会复杂的多关系枚举、隐式语义判断和完整 span 边界，因此没有超过容量更大且配有优化 Prompt 与 RAG1 的 Gemma 31B。

#### CNC 实验综合结论

从完整测试结果看，不同方法改善了 CNC 任务的不同环节，却没有形成统一的增益模式。微调对 detection 最有效，Qwen3-14B QLoRA 的 Detection F1 达到 0.849；此前统一运行的 RAG1 平均增益较小，但在 Gemma 31B 上同时改善 detection、all-samples extraction 和 detected-only extraction。相反，部分模型只改善 detection 或辅助 Anchor 指标，主抽取指标没有同步提高。这说明 CNC 的核心困难不只是判断句子是否包含因果关系，还包括恢复全部关系、确定正确方向、处理隐式因果语义以及生成与 Gold 标注一致的完整事件 span。Qwen validation 上 RAG3 的正向结果说明，家族特定参数可以减少共享 k 带来的配置偏差，但仍需与完整 test 结果分开解释。

在这一背景下，Gemma 4 31B QAT + Fixed 10-shot + RAG1 提供了最均衡的最终结果。其 Detection F1 为 0.844，与 BoschAI｜CASE 2023 的 0.8466 接近；Anchor detected-only F1 为 0.739，在数值上高于 BoschAI FairEval 的 0.7279，但由于两者评估协议不同，这一差值只能说明本地系统达到相近的数值水平，不能解释为严格复现或显著超过官方系统。RAG1 在单模型上的 Anchor all F1 变化范围为 −0.015 至 +0.019，宏平均增益为 +0.006，因此本研究将其结论限定为小幅、总体正向且具有模型依赖性的辅助增强。综合 detection、端到端抽取和已检出样本质量，最终选择 Gemma 31B + RAG1 作为 CNC 本地抽取系统；这一选择来自其完整 test 上的综合表现，而不是对单个最高分或 test 后重新调参的追求。

## 附录 A：LM Studio Prompt Cache 异常与推理稳定性控制

**异常表现。** Qwen3.6 27B No Thinking 在长批量评测后段出现达到输出上限的重复或不完整内容，并连续产生非法 JSON 与兜底结果。请求仍返回 HTTP 200；缩短模型重载间隔也未消除异常。

**排查证据。** 异常样本的 prompt 长度明显低于 context limit，reasoning tokens 为 0，因此不是上下文溢出或思考模式造成。保持模型、Prompt、RAG 和解码参数不变，仅设置 `cache_prompt=False` 后，固定异常区间的 47 条定点测试以及后续 538 条正式续跑均实现生成失败 0、JSON 修复 0。结果表明问题来自当前 LM Studio 本地推理运行时的 prompt cache 状态，而非特定样本或模型抽取能力。

**解决方法。** 后续 LM Studio OpenAI-compatible 评测统一设置 `cache_prompt=False`，并在实验配置中记录该参数。关闭该缓存不改变模型权重、Prompt、RAG 或评价协议，只关闭推理侧的前缀/KV 缓存复用；代价是可能降低生成吞吐速度。
